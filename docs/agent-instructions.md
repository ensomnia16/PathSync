## PathSync：agent 输出与同步约定

- 在规划需要长期保留的成果位置前，用 `~/.local/bin/pathsync rules --json` 读取当前 Mac 的实际规则；规则来自 OneDrive 根目录的 `PathSync-Exclusions.json`，仅云端策略来自本机配置。不要把规则清单硬编码到提示词里，也不要假定两台 Mac 的仅云端策略相同。
- 写入最终报告、论文/汇报材料、图表、重要数据或不可重建的实验结果前，运行 `~/.local/bin/pathsync check-path "目标绝对路径" --json`；尚未创建的目录加 `--directory`。正常上传范围返回 0；排除、仅云端、符号链接/协议保留路径返回 3；未纳入同步、组未启用、仅下载或云端镜像返回 4；无法读取真实规则返回 2，不能视为允许。
- 重要成果的唯一副本不得放在命中排除规则的路径，或此 Mac 已暂停上传的仅云端工作目录。构建缓存、可重建帧、临时解压和中间产物可以留在明确的临时/排除位置；最终成果应另存到经检查的保留位置。目录名 `tmp`、`.build`、`results`、`output` 本身不代表被排除，必须实际检查。不要自动排除唯一实验结果或为绕过检查修改同步规则。
- 用户已明确指定路径、或项目本身处于仅云端/未管理范围时，遵循用户指令和项目已有的 Git、远程发布或备份约定，并说明本机 PathSync 是否会上传。不要擅自迁移现有项目、取消仅云端、改排除配置或删除旧成果。当前环境没有 PathSync 时也不要宣称文件已同步。
- Agent 使用 `pathsync status --json` 查看状态，`pathsync preview --pair "组名" --json` 预览，`pathsync sync --pair "组名" --json` 按保存方向同步，`pathsync stop --json` 请求停止当前任务（作用于整个运行）。实际同步仅在用户已授权时执行；规则查询和路径检查不触发业务文件下载。不要直接用 `sync_merge.py`、`sync_tree.py` 或另写 rsync 绕过根配置、同步锁、冲突及备份保护。
- `check-path` 只证明路径符合当前配置，不证明文件已上传 OneDrive。以同步状态、实际结果和已有发布/备份凭据确认交付；不要把“本机文件存在”当成“云端已有”。
