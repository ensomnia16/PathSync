# 路径同步 / PathSync

轻量 macOS 文件夹同步工具。适合在本地频繁编译 LaTeX 等会产生大量小文件的项目，再按较长间隔同步到 OneDrive 或其他已挂载的目标目录。

## 下载

[下载 Apple Silicon 版应用](https://github.com/ensomnia16/PathSync/releases/tag/v2.15.0)（macOS 13+）。下载包未经过 Apple 公证；也可按下文在本机从源码构建。

## 功能

- 添加多组本地目录和目标目录；每组可独立启用、命名和设置定时同步方向。
- 每组可分别选择同步 Codex 项目文件（`AGENTS.md`、`.codex/`、`.agents/`）、Claude Code 项目文件（`CLAUDE.md`、`.claude/`、`.mcp.json`），以及 `tmp`、`temp`、`.tmp`、`.log` 等临时文件。Claude Code 的 `.claude/settings.local.json`、系统的 `.DS_Store` 始终跳过。新路径默认跳过临时文件；旧配置保持原来的临时文件行为。更改过滤规则不会删除已同步副本。
- 可选通过同一 Apple ID 的 iCloud Drive 共享配置：保存设置时发布路径组名称、相对本机工作根目录及 OneDrive 根目录的路径、同步方向、计划与规则。另一台 Mac 的本机工作根目录默认为 `~/Documents`；导入时自动推导并创建缺失的本地空目录，预览中可核对全部路径。旧版配置未提供本地相对路径时，会从 OneDrive 相对路径推导（例如 `文档/研三/CityU Meeting` → `~/Documents/研三/CityU Meeting`）。绝对路径、启用状态、同步记录、备份与文件内容不会作为配置上传。新增或重新绑定的路径组保持关闭，确认后再启用同步。
- 定时双向合并：相对上次共同内容（anchor）只有一侧更新时复制该侧；两侧都更新且内容不同才按冲突策略处理。可选择保留两份、暂停手动处理，或按绝对修改日期采用较新的版本；日期相同则暂停。
- 自动保留时，先备份两侧原件，再将原路径文件及带版本标记的冲突副本放在两侧；冲突会持续显示为“待人工合并”，直到明确确认处理完成。
- 应用在重新获得焦点时及打开期间定期刷新后台任务产生的冲突，也可手动刷新。
- 窗口顶部可立即同步全部路径或当前路径；也可手动执行双向合并、本地 → 目标、目标 → 本地。
- “同步记录”页面按时间列出每组路径的方向、结果与文件数量；可筛选路径和需关注的记录，展开查看冲突及失败文件。记录中的文件可打开、在 Finder 定位；LaTeX 文本可查看当前版本的统一差异及离线章节/行数摘要。安装了 Codex CLI 时，可主动点击按钮，让 CLI 解读所选差异。原始日志只作为排查入口。
- “默认计划”独立入口：可选择每天的任意同步时间，或设置 6–168 小时的间隔；所有已启用路径共用此计划，各路径可单独选择方向。
- 菜单栏常驻入口可查看待处理版本数、立即同步全部路径、打开主窗口或同步记录；关闭主窗口后仍可从菜单栏重新打开。
- 应用从菜单栏运行，运行时不占用 Dock 位置；退出应用不会关闭已安装的定时同步任务。
- “设置 → 通用”可开启登录后启动，使用 macOS 登录项；如系统要求批准，应用会显示提示。定时同步任务与登录项分别控制。
- 同步通知可选择关闭、仅在冲突或失败时提醒，或每次同步后提醒。默认关闭；主动开启时才请求 macOS 通知权限。通知不包含文件名或路径。
- 界面支持简体中文、英文和跟随系统语言；应用名称也会随系统语言显示。
- 更新：启动后及每天最多一次向 GitHub 查询最新发布的安装包（可在“设置 → 通用”关闭），也可手动检查。发现带签名的新版时，可在应用内安装并重新打开，或在“关于”页选择自动安装。安装包使用内置 Ed25519 公钥校验，验证失败不替换应用。旧版 2.14.1 需要先手动安装本版，此后才支持应用内安装。未发布的 `main` 提交不会触发更新；检查不发送文件名或路径。
- 界面采用 SwiftUI 原生侧栏、分组表单、系统控件与工具栏：“概览”集中显示整体状态、上次同步和计划间隔或下次固定时间，以及各路径卡片；“同步路径”编辑单组路径与冲突；“设置”分组管理计划、冲突与备份、过滤、通知和语言；未保存的更改会在底部状态栏提示。蓝釉图标用单轴双向箭头表示路径往返。
- 删除和编辑都相对同一个 anchor 判断：只有一侧改变时按方向传播该侧状态，删除与编辑并发时暂停该文件。确认执行删除前先备份仍存在的版本。三个方向共用变更基线。默认过滤 LaTeX 中间文件、虚拟环境和缓存。
- 一侧删除曾同步的目录，而另一侧增删或修改了内部文件时，暂停整个目录及其子项的自动处理；可在两侧文件夹中手动核对并使其一致，再刷新冲突列表。目录外的文件继续同步。
- 所有实际覆盖和传播删除都会先生成经校验的本机备份；同步记录中可按文件恢复。默认保留 15 天，可调整为 1–365 天；到期后在后续同步中清理。恢复若覆盖当前文件，会先备份当前版本。
- 逐文件处理；某个云端占位文件读取失败时，继续处理其他文件，并记录到日志。

首次同步遇到同名且内容不同的文件也会自动保留两份。双向合并和本地 → 云端时，本地版本保留在原路径，云端版本以带 `cloud conflict` 标记的副本出现在两侧；云端 → 本地时则由云端版本占原路径，本地版本以 `local conflict` 标记。原件会先备份到 `~/Library/Application Support/ResearchSync/merge-state/<路径组 ID>-conflict-backups/`。**保留两份只保证两个版本都不丢失，并不会把内容合入主文件。**待合并项会在路径页和之后每次同步记录中持续提示；可打开主文件与另一版本进行人工合并，完成后点击“确认已处理”。确认前两侧主文件必须一致，确认也不会删除冲突副本。如在默认计划中选择“暂停并手动选择”，冲突会保存在 `merge-state/` 并显示在对应路径组，仍可选择本地、云端或保留两份。每次运行按路径组记录上传、下载、删除、备份、待处理冲突和失败数量。

建议先让云盘客户端下载需要的文件，再使用“目标 → 本地”。工具不能替代云盘客户端获取尚未下载的占位文件内容。

## 构建

需要 macOS 13 或更新版本、Xcode Command Line Tools。运行：

```sh
./build.sh
```

生成的应用位于 `.build/路径同步.app`。复制到 `/Applications` 后打开，在应用中选择目录并点击“保存设置”。定时任务以当前登录用户身份通过 `launchd` 运行；无需管理员权限运行同步。

当前图标源图是 `PathSyncIcon.png`，由选定的“轨道梭”方案直接生成；旧版 `GenerateIcon.swift` 仅保留作历史参考。应用内“关于”页面可以选择界面语言。

## 命令行

应用包中的 `Contents/MacOS/ResearchSync` 支持：

```text
--sync                  按每组保存的方向同步所有已启用路径
--push                  所有已启用路径：本地 → 目标
--pull                  所有已启用路径：目标 → 本地
--merge                 所有已启用路径：双向合并
--dry-run               预览，不复制
--pair UUID             只运行指定路径组
--config PATH           读取指定配置文件
--resolve RELATIVE_PATH --choice local|cloud|both|newest --pair UUID
                       处理指定路径组中的一个待处理冲突
--acknowledge RELATIVE_PATH --pair UUID
                       确认已检查保留的两个版本；保留副本与备份
--review-newest RELATIVE_PATH --pair UUID
                       对当前主文件与保留副本采用修改日期较新的版本
--restore-backup ID --pair UUID
                       恢复同步记录中的一个备份；覆盖当前文件前再次备份
--install               安装或更新当前用户的定时任务
```

配置和日志保存在 `~/Library/Application Support/ResearchSync/`，定时任务位于 `~/Library/LaunchAgents/com.ensom.ResearchSync.plist`。应用保留内部标识 `ResearchSync`，以便从旧版本迁移配置。

开启 iCloud 配置后，每台 Mac 的配置快照单独写到 iCloud Drive 的 `PathSync/Configuration/<设备 UUID>.json`，避免多台机器同时覆盖同一文件。导入前先保存本机设置；导入时先预览路径和规则变化。如果本机修改过上次导入的共享规则，会提示覆盖风险；可以取消或采用远端规则。导入后再次保存，才会更新本机计划。新导入或重新绑定的路径组默认停用；远端删除某个路径组不会直接删掉本机路径组。设备列表显示本机 iCloud 上传状态、其他 Mac 最近收到的配置，以及对方是否报告导入本机当前版本。状态以 iCloud Drive 在本机提供的信息为准，并不证明另一台 Mac 已执行文件同步。旧版配置中的空“新路径”占位项会被忽略。仅在开启此选项后访问 iCloud Drive；Apple ID 登录和 iCloud Drive 开关由 macOS 管理。此功能不在定时文件同步任务中读取远端配置，也不自动改变另一台 Mac 的运行路径。

每次保存有变化的本机配置前，应用会保留一个旧版快照，最多保留 20 份。在“设置 → 配置回退”载入旧版后，可先检查草稿；保存前不能手动同步或恢复文件。跨组路径若相同或相互包含，保存和执行前会拒绝，以免同一目录被多个基线写入。

记录页直接整理已有的 `sync.log`，旧同步记录也能查看；只显示当前已配置路径组的记录。普通上传/下载显示数量，冲突与失败会列出文件名。最多加载日志末尾 2 MB，并显示最近 200 条记录。

## 同步规则

三个方向使用同一份上次成功处理的文件状态判断哪侧更新。新状态保存共同内容的 SHA-256；旧状态没有哈希时，会从未变动的一侧推断，无法推断时保守地视作冲突。自动处理冲突的绝对日期选项只在两侧都相对 anchor 更新时比较文件的修改时间，依赖设备时钟正确；同一时间戳不自动选择。若较新版本与明确选择的单向方向相反，也会暂停而不反向复制。已保留版本的手动日期操作则比较当前主文件与保留副本的修改时间；每个版本必须已在两侧同步一致。复制和冲突处理前会检查文件是否又发生变化。保留两份时首先在本地保存并校验两侧原件，然后才更新同步路径。手动同步使用已保存的配置；有未保存的更改时会暂停手动操作。首次使用前请核对路径和定时模式。

同步状态、依据和目前尚未解决的目录级冲突与 OneDrive 可见性边界，见[同步模型说明](docs/synchronization-model.md)。已保留版本上的“采用当前较新版本”比较当前主文件和冲突副本的修改时间。保留副本必须在两侧一致；主文件若两侧不同，只有一侧相对 anchor 更新时，才会在同一次操作中备份并传播该侧。两侧都更新则暂停。主文件在保留后继续更新也可选择，但请先确认较新文件的内容符合预期。

从 2.11.0 起不再有单独的删除传播开关；旧配置中的 `propagateDeletions` 字段会在读取时忽略，下一次保存设置时移除。升级前可先用 `--dry-run` 查看真实路径的计划操作。

可恢复备份位于 `~/Library/Application Support/ResearchSync/merge-state/<路径组 ID>-backups/`，每个备份含校验信息。同步记录显示对应文件、打开/定位入口和恢复按钮；过期后恢复按钮消失。记录中的文件操作针对当前磁盘文件，旧记录本身不保存文件快照。此前版本创建的 `-conflict-backups/` 不会被新保留期自动清理。

如果 OneDrive 等云盘文件提供程序返回 `Operation timed out`，表示本次未能读到该文件内容；检查云盘客户端下载状态后重试。日志会记录失败文件。
