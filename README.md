# 路径同步 / PathSync

轻量 macOS 文件夹同步工具。适合在本地频繁编译 LaTeX 等会产生大量小文件的项目，再按较长间隔同步到 OneDrive 或其他已挂载的目标目录。

## 下载

[下载 Apple Silicon 版应用](https://github.com/ensomnia16/PathSync/releases/tag/v2.9.0)（macOS 13+）。下载包未经过 Apple 公证；也可按下文在本机从源码构建。

## 功能

- 添加多组本地目录和目标目录；每组可独立启用、命名和设置定时同步方向。
- 定时双向合并：相对上次共同内容（anchor）只有一侧更新时复制该侧；两侧都更新且内容不同才按冲突策略处理。可选择保留两份、暂停手动处理，或按绝对修改日期采用较新的版本；日期相同则暂停。
- 自动保留时，先备份两侧原件，再将原路径文件及带版本标记的冲突副本放在两侧；冲突会持续显示为“待人工合并”，直到明确确认处理完成。
- 应用在重新获得焦点时及打开期间定期刷新后台任务产生的冲突，也可手动刷新。
- 窗口顶部可立即同步全部路径或当前路径；也可手动执行双向合并、本地 → 目标、目标 → 本地。
- “同步记录”页面按时间列出每组路径的方向、结果与文件数量；可筛选路径和需关注的记录，展开查看冲突及失败文件。原始日志只作为排查入口。
- “默认计划”独立入口：可选择每天的任意同步时间，或设置 6–168 小时的间隔；所有已启用路径共用此计划，各路径可单独选择方向。
- 界面支持简体中文、英文和跟随系统语言；应用名称也会随系统语言显示。
- 界面采用 SwiftUI 原生侧栏、分组表单、系统控件与工具栏；蓝釉图标用单轴双向箭头表示路径往返。
- 默认不传播删除；可单独启用。启用后，单侧删除要连续两次同步仍缺失且另一侧相对 anchor 未改，才会传播；删除与编辑并发时暂停该文件。三个方向共用变更基线。默认过滤 LaTeX 中间文件、虚拟环境和缓存。
- 所有实际覆盖和传播删除都会先生成经校验的本机备份；同步记录中可按文件恢复。默认保留 15 天，可调整为 1–365 天；到期后在后续同步中清理。恢复若覆盖当前文件，会先备份当前版本。
- 逐文件处理；某个云端占位文件读取失败时，继续处理其他文件，并记录到日志。

首次同步遇到同名且内容不同的文件也会自动保留两份。双向合并和本地 → 云端时，本地版本保留在原路径，云端版本以带 `cloud conflict` 标记的副本出现在两侧；云端 → 本地时则由云端版本占原路径，本地版本以 `local conflict` 标记。原件会先备份到 `~/Library/Application Support/ResearchSync/merge-state/<路径组 ID>-conflict-backups/`。**保留两份只保证两个版本都不丢失，并不会把内容合入主文件。**待合并项会在路径页和之后每次同步记录中持续提示；可打开主文件与另一版本进行人工合并，完成后点击“确认已处理”。确认前两侧主文件必须一致，确认也不会删除冲突副本。如在默认计划中选择“暂停并手动选择”，冲突会保存在 `merge-state/` 并显示在对应路径组，仍可选择本地、云端或保留两份。未启用删除传播时，单侧缺失的文件会从另一侧恢复。每次运行按路径组记录上传、下载、删除、备份、待处理冲突和失败数量。

建议先让云盘客户端下载需要的文件，再使用“目标 → 本地”。工具不能替代云盘客户端获取尚未下载的占位文件内容。

## 构建

需要 macOS 13 或更新版本、Xcode Command Line Tools。运行：

```sh
./build.sh
```

生成的应用位于 `.build/路径同步.app`。复制到 `/Applications` 后打开，在应用中选择目录并点击“保存设置”。定时任务以当前登录用户身份通过 `launchd` 运行；无需管理员权限运行同步。

当前图标源图是 `PathSyncIcon.png`，由选定的“轨道梭”方案直接生成；旧版 `GenerateIcon.swift` 仅保留作历史参考。应用内“关于”页面可以选择界面语言。

## 命令行

应用包中的 `Contents/MacOS/ResearchSync` 支持：

```text
--sync                  按每组保存的方向同步所有已启用路径
--push                  所有已启用路径：本地 → 目标
--pull                  所有已启用路径：目标 → 本地
--merge                 所有已启用路径：双向合并
--dry-run               预览，不复制
--pair UUID             只运行指定路径组
--config PATH           读取指定配置文件
--resolve RELATIVE_PATH --choice local|cloud|both|newest --pair UUID
                       处理指定路径组中的一个待处理冲突
--acknowledge RELATIVE_PATH --pair UUID
                       确认已检查保留的两个版本；保留副本与备份
--review-newest RELATIVE_PATH --pair UUID
                       对已保留的两个版本采用原始修改日期较新的版本
--restore-backup ID --pair UUID
                       恢复同步记录中的一个备份；覆盖当前文件前再次备份
--install               安装或更新当前用户的定时任务
```

配置和日志保存在 `~/Library/Application Support/ResearchSync/`，定时任务位于 `~/Library/LaunchAgents/com.ensom.ResearchSync.plist`。应用保留内部标识 `ResearchSync`，以便从旧版本迁移配置。

记录页直接整理已有的 `sync.log`，旧同步记录也能查看；只显示当前已配置路径组的记录。普通上传/下载显示数量，冲突与失败会列出文件名。最多加载日志末尾 2 MB，并显示最近 200 条记录。

## 同步规则

三个方向使用同一份上次成功处理的文件状态判断哪侧更新。新状态保存共同内容的 SHA-256；旧状态没有哈希时，会从未变动的一侧推断，无法推断时保守地视作冲突。绝对日期选项只在两侧都相对 anchor 更新时比较文件的修改时间，依赖设备时钟正确；同一时间戳不自动选择。若较新版本与明确选择的单向方向相反，也会暂停而不反向复制。已保留的版本使用当时记录的原始修改时间，文件后来若被改动则拒绝自动选择。复制和冲突处理前会检查文件是否又发生变化。保留两份时首先在本地保存并校验两侧原件，然后才更新同步路径。手动同步所选路径可在保存该路径前运行；后台任务只读取已保存的配置。首次使用前请核对路径和定时模式。

可恢复备份位于 `~/Library/Application Support/ResearchSync/merge-state/<路径组 ID>-backups/`，每个备份含校验信息。同步记录显示对应文件和恢复按钮；过期后按钮消失。此前版本创建的 `-conflict-backups/` 不会被新保留期自动清理。

如果 OneDrive 等云盘文件提供程序返回 `Operation timed out`，表示本次未能读到该文件内容；检查云盘客户端下载状态后重试。日志会记录失败文件。
