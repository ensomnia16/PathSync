# 路径同步 / PathSync

轻量 macOS 文件夹同步工具。适合在本地频繁编译 LaTeX 等会产生大量小文件的项目，再按较长间隔同步到 OneDrive 目标目录。

## 下载

[下载 Apple Silicon 版应用](https://github.com/ensomnia16/PathSync/releases/latest)（macOS 13+）。下载包未经过 Apple 公证；也可按下文在本机从源码构建。

## 功能

- 添加多组本地目录和目标目录；每组可独立启用、命名和设置定时同步方向。
- 单组页面可选择“仅云端子路径”，各台 Mac 独立保存。填写具体相对子路径并保存后，普通上传、下载及删除传播都会跳过该子树；添加设置不会删除现有文件，也不写入 OneDrive 根排除配置。
- “释放工作副本”先逐文件核对本机工作目录与 OneDrive 目标镜像的大小和 SHA-256，包括隐藏文件。目标缺失、内容不同、冲突、符号链接或读取失败会阻止释放；校验通过后才移除工作目录中的副本。请先在 OneDrive 客户端确认上传完成：镜像一致不证明服务器已收到文件。校验可能下载目标镜像；如需继续释放 OneDrive 自身缓存，请在 Finder 的目标路径上选择“释放空间”。
- “恢复正常同步”并保存后，按该组原方向执行。双向合并或目标 → 本地可以重新下载；本地 → 目标不会强制反向下载。已释放副本的缺失不会作为云端删除传播。释放过程中使用独立恢复记录；异常时界面显示暂存位置，保留的暂存数据可用于恢复。
- 所有用户排除项都显式写在 OneDrive 根配置的 `excludeRules` 中。共享模式不会额外过滤日志、LaTeX 输出、临时目录、技能或项目配置；仅保留同步传输临时文件、退休规则文件和符号链接的协议保护。
- 定时双向合并：相对上次共同内容（anchor）只有一侧更新时复制该侧；两侧都更新且内容不同才按冲突策略处理。可选择保留两份、暂停手动处理，或按绝对修改日期采用较新的版本；日期相同则暂停。
- 自动保留时，先备份两侧原件，再将原路径文件及带版本标记的冲突副本放在两侧；同步随即完成，不需要手动确认。同步记录会列出冲突副本的名称，通知按设置提醒。
- 应用在重新获得焦点时及打开期间定期刷新后台任务产生的冲突，也可手动刷新。
- 窗口顶部可立即同步全部路径或当前路径；也可手动执行双向合并、本地 → 目标、目标 → 本地。
- “同步记录”页面按时间列出每组路径的方向、结果与文件数量；可筛选路径和需关注的记录，展开查看冲突及失败文件。记录中的文件和覆盖前备份可打开、在 Finder 定位；LaTeX 文本可查看统一差异及离线章节/行数摘要。覆盖前备份记录比较保存的旧版与当前对应文件；其他记录比较当前两侧或冲突副本。安装了 Codex CLI 时，可主动点击按钮，让 CLI 解读所选差异。原始日志只作为排查入口。
- “默认计划”独立入口：可选择每天的任意同步时间，或设置 1–168 小时的间隔；所有已启用路径共用此计划，各路径可单独选择方向。
- 应用启动时打开独立窗口，并常驻菜单栏。关闭主窗口后保留菜单栏图标并从 Dock 隐藏；可从菜单栏重新打开主窗口、查看同步记录或立即同步。只有选择“退出路径同步”才退出常驻程序；已安装的定时同步任务仍按计划运行。
- “设置 → 通用”可开启登录后启动，使用 macOS 登录项；如系统要求批准，应用会显示提示。定时同步任务与登录项分别控制。
- 同步通知可选择关闭、仅在冲突或失败时提醒，或每次同步后提醒。默认关闭；主动开启时才请求 macOS 通知权限。通知不包含文件名或路径。
- 界面支持简体中文、英文和跟随系统语言；应用名称也会随系统语言显示。
- 更新：启动后及每天最多一次向 GitHub 查询最新发布的安装包（可在“设置 → 通用”关闭），也可手动检查。发现带签名的新版时，可在应用内安装并重新打开，或在“关于”页选择自动安装。安装包使用内置 Ed25519 公钥校验，验证失败不替换应用。旧版 2.14.1 需要先手动安装本版，此后才支持应用内安装。未发布的 `main` 提交不会触发更新；检查不发送文件名或路径。
- 界面采用 SwiftUI 原生侧栏、分组表单、系统控件与工具栏：“概览”显示整体状态、各路径卡片（方向、状态、预览与同步）和跨路径的“待处理”列表；单组路径页编辑名称、文件夹、方向，并查看规则来源与冲突；“设置”一页管理计划、冲突与备份、通用、软件更新、OneDrive 排除规则、配置回退与关于；未保存的更改会在底部状态栏提示。
- 排除规则只读取所选 OneDrive 根目录的 `PathSync-Exclusions.json`，按目标文件夹相对 OneDrive 根目录的路径匹配各组规则。旧过滤开关应设为 `excludeLatexIntermediates: false`，三个 `sync…Files: true`；开启旧批量过滤会报错，避免隐含排除。
- 每次预览和同步重新读取根配置；本地 `config.json`、历史配置和两端 `.pathsyncignore` 均不提供排除规则。应用不创建、合并或写回根规则，保存设置只保存本机路径、方向、计划等设置。规则缺失、无效或缺少本次路径组条目时，停止该次操作并报错。
- 单组路径页显示根配置位置和已载入规则数，可在 Finder 中定位文件。设置中可选择 OneDrive 根目录。规则格式见 [配置示例](docs/exclusions.example.json)；每行一条，支持 `*`、`?`、`**`，结尾 `/` 匹配目录，开头或中间 `/` 从该组根目录匹配。排除项保留两端已有副本和同步基线。
- 同步前检查云盘（设置中默认开启）：路径位于 `~/Library/CloudStorage` 时，如果 OneDrive 没有运行，或文件夹 20 秒内没有响应，这组路径本次跳过，并在同步记录中说明原因，不会把读不到的文件当作删除。需要比较内容的仅在线（占位）文件会先下载，沿用现有的读取时限；预览只统计这些文件的数量，不触发下载。
- 同步运行时可在工具栏、同步详情或菜单栏点击“停止同步”。会保留已完成的文件与基线，清理未发布的临时副本并取消本次下载读取；再次同步继续处理剩余文件。停止不会更改自动同步计划或每台 Mac 的仅云端设置。
- OneDrive 索引中的 `.pkgf` 包项目按 Finder 包标记及 File Provider 原始名称映射；系统为重名包添加的“2”会保留。普通同名文件不参与包映射，包按整体复制并核验，包含空目录、资源分叉和内部链接；重名歧义或两侧包内容不同时保留两边并报告具体路径。
- 同步前预览：在概览、工具栏或单组路径页点击“预览”，按路径组列出将要上传、下载、删除（先备份）的文件，以及冲突和无法读取的文件。预览只读取，不写入任何文件，也不会让 OneDrive 下载仅在线的新文件；确认后按相同范围执行同步。后台定时同步不经过预览。
- 最多 3 组路径同时同步，仍共用一个同步锁；各组的合并状态和备份互相独立。应用在后台读取冲突状态和同步日志，日志只读取新增部分。
- 备份存放位置可选本机（默认）、iCloud Drive（`PathSync/Backups/<路径组 ID>`）或自选的 OneDrive 等文件夹，冲突备份和覆盖前备份都放在那里，写入后逐个校验。所选位置不可用或写入失败时先存放在本机，下一次同步时再移过去；恢复和过期清理两处都会查找。备份文件夹不能位于同步路径内，也不能包含同步路径。“把现有备份移过去”会逐个复制、校验后再删除本机副本。合并状态始终保存在本机。
- 删除和编辑都相对同一个 anchor 判断：只有一侧改变时按方向传播该侧状态，删除与编辑并发时暂停该文件。确认执行删除前先备份仍存在的版本。三个方向共用变更基线。过滤范围由根配置明确列出。
- 一侧删除曾同步的目录，而另一侧增删或修改了内部文件时，暂停整个目录及其子项的自动处理；可在两侧文件夹中手动核对并使其一致，再刷新冲突列表。目录外的文件继续同步。
- 所有实际覆盖和传播删除都会先生成经校验的本机备份；同步记录中可按文件恢复。默认保留 15 天，可调整为 1–365 天；到期后在后续同步中清理。恢复若覆盖当前文件，会先备份当前版本。
- 逐文件处理；某个云端占位文件读取失败时，继续处理其他文件，并记录到日志。
- 符号链接不参与文件同步。曾同步的普通文件或目录改为符号链接后，该路径及子项会在两端同时跳过，保留已有副本与同步基线；不跟随链接，也不传播删除。预览和同步记录会列出跳过项。恢复为普通文件后重新按原基线比较。
- 扫描 OneDrive 等文件提供程序时显示已检查的目录和文件数量；首次导入大量云端文件时并行预读，优先复制较小的新文件。云端预读最多同时处理 4 个文件，按大小给予 120–300 秒读取时间，并持续显示等待时长；超过上限会记录失败并继续。云端仅 ctime 变化或修改时间被截到整秒时，不再重新读取全部未变动文件；任一侧有明确更新时仍核验两侧内容。连续 3 分钟没有进度时停止当前路径，其他路径继续运行。

首次同步遇到同名且内容不同的文件也会自动保留两份。双向合并和本地 → 云端时，本地版本保留在原路径，云端版本以带 `cloud conflict` 标记的副本出现在两侧；云端 → 本地时则由云端版本占原路径，本地版本以 `local conflict` 标记。原件会先备份到 `~/Library/Application Support/ResearchSync/merge-state/<路径组 ID>-conflict-backups/`。**保留两份只保证两个版本都不丢失，并不会把内容合入主文件**；需要时可在同步记录中打开两个版本自行合并。自动保留不会留下待处理项，旧版本留下的“待人工合并”记录也会在下一次按自动保留策略同步时清除。只有在默认计划中选择“暂停并手动选择”时，冲突才会保存在 `merge-state/` 并显示在概览的“待处理”中，可选择本地、云端或保留两份；手动选择保留两份后，此项显示为待人工合并，合并完成后点击“确认已处理”（确认前两侧主文件必须一致，确认不会删除冲突副本）。每次运行按路径组记录上传、下载、删除、备份、待处理冲突和失败数量。

建议先让云盘客户端下载需要的文件，再使用“目标 → 本地”。工具不能替代云盘客户端获取尚未下载的占位文件内容。

## 构建

需要 macOS 13 或更新版本、Xcode Command Line Tools。运行：

```sh
./build.sh
```

生成的应用位于 `.build/路径同步.app`。复制到 `/Applications` 后打开，在应用中选择目录并点击“保存设置”。定时任务以当前登录用户身份通过 `launchd` 运行；无需管理员权限运行同步。

当前图标源图是 `PathSyncIcon.png`，采用白底双层抽屉柜：蓝色抽屉、白色拉手，主体在底板内留出更多空间；`app-icon/provenance.json` 记录最终图标来源，`tools/package-legacy-icon.swift` 为现有 `.icns` 打包路径生成圆角及留白。原始方形源图保留；旧版 `GenerateIcon.swift` 仅保留作历史参考。应用内“关于”页面可以选择界面语言。

## 快捷指令

在“快捷指令”中用“打开 URL”动作：

```text
pathsync://sync                 按各组设定的方向同步全部已启用路径
pathsync://sync?pair=ID或名称    只同步一组路径（路径组 ID，或唯一的路径名称）
pathsync://open                 打开主窗口
```

有未保存的设置或已有同步在运行时，同步请求会被忽略。获取同步状态可用“运行 Shell 脚本”动作执行 `/Applications/路径同步.app/Contents/MacOS/PathSync --status`，它以 JSON 输出每组路径的上次同步时间、结果和待处理冲突数，以及是否正在同步；该命令只读取，不同步。

目前用 `build.sh`（只需命令行工具，不需要 Xcode）构建，无法生成 App Intents 所需的元数据，因此快捷指令里不会出现“同步全部路径”等原生动作；需要用 Xcode 工程构建时才能加入。

## 命令行

应用包中的 `Contents/MacOS/PathSync` 支持：

```text
--sync                  按每组保存的方向同步所有已启用路径
--push                  所有已启用路径：本地 → 目标
--pull                  所有已启用路径：目标 → 本地
--merge                 所有已启用路径：双向合并
--dry-run               预览，不复制
--pair UUID             只运行指定路径组
--config PATH           读取指定配置文件
--resolve RELATIVE_PATH --choice local|cloud|both|newest --pair UUID
                       处理指定路径组中的一个待处理冲突
--acknowledge RELATIVE_PATH --pair UUID
                       确认已检查保留的两个版本；保留副本与备份
--review-newest RELATIVE_PATH --pair UUID
                       对当前主文件与保留副本采用修改日期较新的版本
--restore-backup ID --pair UUID
                       恢复同步记录中的一个备份；覆盖当前文件前再次备份
--status                以 JSON 输出各组路径的同步状态（只读）
--install               安装或更新当前用户的定时任务
```

配置和日志保存在 `~/Library/Application Support/ResearchSync/`，定时任务位于 `~/Library/LaunchAgents/com.ensom.ResearchSync.plist`。可执行入口名为 `PathSync`；旧的 `ResearchSync` 命令别名、bundle identifier 和配置目录保留兼容。后台计划通过 `AssociatedBundleIdentifiers` 关联应用名称和图标；启动时迁移旧计划且不改变同步间隔。

每次保存有变化的本机配置前，应用会保留一个旧版快照，最多保留 20 份。在“设置 → 配置回退”载入旧版后，可先检查草稿；保存前不能手动同步或恢复文件。跨组路径若相同或相互包含，保存和执行前会拒绝，以免同一目录被多个基线写入。

记录页直接整理已有的 `sync.log`，旧同步记录也能查看；只显示当前已配置路径组的记录。普通上传/下载显示数量，冲突与失败会列出文件名。最多加载日志末尾 2 MB，并显示最近 200 条记录。

## 同步规则

三个方向使用同一份上次成功处理的文件状态判断哪侧更新。新状态保存共同内容的 SHA-256；旧状态没有哈希时，会从未变动的一侧推断，无法推断时保守地视作冲突。自动处理冲突的绝对日期选项只在两侧都相对 anchor 更新时比较文件的修改时间，依赖设备时钟正确；同一时间戳不自动选择。若较新版本与明确选择的单向方向相反，也会暂停而不反向复制。已保留版本的手动日期操作则比较当前主文件与保留副本的修改时间；每个版本必须已在两侧同步一致。复制和冲突处理前会检查文件是否又发生变化。保留两份时首先在本地保存并校验两侧原件，然后才更新同步路径。手动同步使用已保存的配置；有未保存的更改时会暂停手动操作。首次使用前请核对路径和定时模式。

同步状态、依据和目前尚未解决的目录级冲突与 OneDrive 可见性边界，见[同步模型说明](docs/synchronization-model.md)。已保留版本上的“采用当前较新版本”比较当前主文件和冲突副本的修改时间。保留副本必须在两侧一致；主文件若两侧不同，只有一侧相对 anchor 更新时，才会在同一次操作中备份并传播该侧。两侧都更新则暂停。主文件在保留后继续更新也可选择，但请先确认较新文件的内容符合预期。

从 2.11.0 起不再有单独的删除传播开关；旧配置中的 `propagateDeletions` 字段会在读取时忽略，下一次保存设置时移除。升级前可先用 `--dry-run` 查看真实路径的计划操作。

可恢复备份位于 `~/Library/Application Support/ResearchSync/merge-state/<路径组 ID>-backups/`，每个备份含校验信息。同步记录显示对应文件、打开/定位入口和恢复按钮；过期后恢复按钮消失。记录中的文件操作针对当前磁盘文件，旧记录本身不保存文件快照。此前版本创建的 `-conflict-backups/` 不会被新保留期自动清理。

如果 OneDrive 等云盘文件提供程序返回 `Operation timed out`，表示本次未能读到该文件内容；检查云盘客户端下载状态后重试。日志会记录失败文件。

菜单栏使用三态抽屉图标：斜杠表示定时同步关闭，循环箭头转动表示正在同步，勾表示已开启。状态依据已保存的计划和真实同步锁计算，约每 2 秒核对一次，因此也能发现独立的后台定时进程。面板提供状态、计划、各路径记录、同步、设置、记录和主窗口入口。应用图标在原白色底板内将柜体缩小 10%，外层底板保持原尺寸。

通用最小规则示例为 11 条：`.venv/`、`.tox/`、`.nox/`、`__pycache__/`、`.pytest_cache/`、`.mypy_cache/`、`.ruff_cache/`、`node_modules/`、`.DS_Store`、`*.pyc`、`*.pyo`。环境目录应可由依赖清单重建；不要用 `env/`、`tmp/`、`*.log` 或实验目录名代替内容判断。文件数量多时先做可验证打包，不能因此直接排除唯一资料。
